# 폰트 매핑 기술 문서

## 문제

게임 대사는 `romfs/Event/event/**/EVENT_MESSAGE_*.ebm`에 UTF-8로 저장됩니다. 그러나 `MainFont_nx_0.g1t`에는 한글 매핑이 없으므로 EBM에 한글을 직접 넣어도 정상 표시되지 않습니다.

폰트 텍스처는 BC3(DXT5) 형식의 2048×1024 아틀라스입니다. 대략 26픽셀 간격의 79×39 격자를 사용하지만, 실제 렌더링 UV의 시작점과 폭·높이는 문자마다 다릅니다.

## 매핑 추출

대사에 2,097개의 한자를 순서대로 넣은 탐침 모드를 실행하고 RenderDoc으로 한 프레임을 캡처했습니다. 폰트 draw call의 정점 수는 `2,138 × 6 = 12,828`이었으며, 각 글리프의 정점 속성에서 UV `float2`를 읽었습니다.

```text
col  = round((u × 2048) / 26)
row  = round(((v × 1024) - 2) / 26)
cell = row × 79 + col
```

기존에 화면으로 수작업 검증한 12자와 모두 일치했습니다. 같은 셀을 공유하는 문자는 후보에서 전부 제외했습니다.

## 실제 UV 사각형

초기 구현은 셀 기준 위치에 모든 한글을 동일하게 그렸고, 화면에서 일부 획이 잘렸습니다. 분석 결과 실제 UV 좌상단은 격자 기준에서 최대 약 ±13픽셀 이동했습니다.

최종 구현은 각 문자의 `min(UV)`와 `max(UV)`로 실제 샘플 사각형을 기록하고, 폭과 높이가 모두 24픽셀 이상인 고유 영역만 사용합니다. 한글은 고정 셀이 아니라 이 실제 사각형 안에 렌더링됩니다.

## BC3 수정

원본 폰트 전체를 재압축하지 않습니다. 선택된 UV 사각형과 맞닿은 BC3 블록의 알파 부분만 다시 기록하고 색상 블록 및 나머지 압축 데이터는 보존합니다.

최종판은 원본 일본어 글리프의 크기와 가독성을 참고해 24×24 이상인 실제 UV 사각형 안에 2픽셀 여백을 두고 약 20×20 크기로 Pretendard Bold를 렌더링합니다. BC4 끝점 255/0 사이의 8단계 보간값을 사용해 안티앨리어싱을 보존합니다. 초기 2단계 이진 알파 방식보다 곡선과 대각선의 계단 현상이 줄어듭니다.

## 텍스트 치환

한글 음절과 선정한 희귀 한자를 1:1로 연결합니다. 두 문자군은 모두 UTF-8에서 3바이트이므로 EBM 레코드 크기가 유지되며, 생성 후 모든 파일을 역치환하여 번역 원본과 바이트 단위로 비교했습니다.

공개 데이터:

- `data/char_to_cell_renderdoc.json`: 문자별 셀 및 UV 사각형
- `data/probe_chars_full.json`: 탐침 문자와 원문 빈도
- `data/final_mod_report.json`: 최종 한글↔대체 문자↔셀 대응표
